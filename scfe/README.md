## 2. Firebase 프로젝트 생성

1. https://console.firebase.google.com 접속 → 구글 계정으로 로그인
2. "프로젝트 추가" → 프로젝트 이름 입력(예: `avsec-hero-2026`) → Google Analytics는 "사용 안 함" 선택해도 무방
3. 프로젝트 생성 완료 후 콘솔 좌측 메뉴에서 두 가지 기능을 켭니다.

### 2-1. Firestore Database 활성화
- 좌측 메뉴 "Firestore Database" → "데이터베이스 만들기"
- 위치: `asia-northeast3 (서울)` 선택 (국내 지연시간 최소화)
- 모드: "프로덕션 모드"로 시작 (규칙은 4단계에서 별도 적용)

### 2-2. Authentication 활성화
- 좌측 메뉴 "Authentication" → "시작하기"
- 로그인 방법에서 "이메일/비밀번호" 활성화
- "Users" 탭 → "사용자 추가" → 관리자용 이메일/비밀번호 등록
  - 아이디 형태로 쓰려면 `staff1@kac.astc` 처럼 가상 도메인을 붙여 등록하면 로그인 화면에서 `staff1`만 입력하면 됩니다.
- ⚠ 보안: "설정" 탭 → 사용자 작업에서 **"생성 사용 설정(가입)"을 해제**해 자가 가입을 차단하세요.
- 계정을 만든 뒤에는 **관리자 페이지 → "관리자 계정" 섹션에서 권한을 부여**해야 로그인이 됩니다. (아래 4-1 참고)

### 2-3. 웹 앱 등록 및 설정값(config) 발급
- 프로젝트 개요 화면 → `</>` (웹) 아이콘 클릭 → 앱 닉네임 입력 → 등록
- 표시되는 `firebaseConfig` 객체 값을 복사

## 3. 코드에 설정값 반영

`js/firebase-config.js` 파일을 열고 아래 값을 2-3단계에서 복사한 값으로 교체:

```js
export const firebaseConfig = {
  apiKey: "여기에 발급받은 값",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "...",
};
```

> apiKey는 클라이언트(브라우저)에 노출되는 값으로, Firebase에서는 이를 비밀키로 취급하지 않습니다.
> 실제 접근 제어는 4단계의 Firestore 보안 규칙이 담당합니다.

## 4. Firestore 보안 규칙 적용

1. Firebase 콘솔 → Firestore Database → "규칙" 탭
2. 이 저장소의 `firestore.rules` 파일 내용을 전체 복사해 붙여넣기 → "게시"
3. ⚠ 확인 필요: 게시 전 "규칙 플레이그라운드"에서 아래 3가지를 직접 시뮬레이션해 의도대로 동작하는지 확인
   - 비로그인 상태로 `participants` 문서 생성(create) → 허용되는지
   - 비로그인 상태로 `rewardGiven` 필드 수정 시도(update) → 거부되는지
   - 로그인 상태로 동일 문서 수정 → 허용되는지

### 4-1. 관리자 권한 구조

권한은 **소유자(owner)** 와 **관리자(admin)** 두 단계입니다.

| 구분 | 정의 위치 | 할 수 있는 일 |
|---|---|---|
| 소유자 | `firestore.rules`의 `isOwner()` 목록 (코드 고정) | 관리자 권한 부여·회수 + 아래 관리자 권한 전부 |
| 관리자 | Firestore `admins` 컬렉션 (관리자 화면에서 관리) | 참가자·행사 관리, 기념품 지급, 데이터 삭제 |

- 계정 **생성**은 항상 Firebase 콘솔에서 하고(자가 가입 차단 상태), 관리자 페이지에서는 **권한만** 부여·회수합니다.
- 소유자 목록을 코드에 고정해 두는 이유는, `admins` 컬렉션이 비어도 **잠금(lockout)이 발생하지 않게** 하기 위한 안전장치입니다.
- 소유자를 바꾸려면 `firestore.rules`의 `isOwner()`와 `js/admin.js`의 `OWNER_EMAILS`를 **함께** 수정하고 규칙을 재게시해야 합니다. (JS 목록은 화면 표시용이고, 실제 권한 판정은 규칙이 담당합니다.)
- 권한이 없는 계정으로 로그인하면 자동으로 로그아웃되며 안내 문구가 표시됩니다.

## 6. GitHub 저장소 업로드 & GitHub Pages 배포

기존 저장소가 있다고 하셨으므로, 해당 저장소 루트(또는 하위 폴더)에 이 폴더 전체를 그대로 업로드합니다.

```bash
# 기존 저장소를 클론한 폴더 기준
cp -r aviation-security-event/* /path/to/your-repo/
cd /path/to/your-repo
git add .
git commit -m "feat: 2026 서울진로직업박람회 이벤트 웹앱 추가"
git push origin main
```

GitHub Pages 활성화:
1. 저장소 → Settings → Pages
2. Source: "Deploy from a branch" 선택
3. Branch: `main` / 폴더: `/ (root)` (하위 폴더에 올렸다면 해당 경로) 선택 → Save
4. 1~2분 후 상단에 표시되는 배포 URL 확인 (예: `https://아이디.github.io/저장소명/`)

> ⚠ 확인 필요: 기존 저장소에 이미 다른 콘텐츠(예: 기존 GitHub Pages 사이트)가 있다면
> 루트에 그대로 덮어쓰지 말고 하위 폴더(`/avsec-event/` 등)에 업로드한 뒤
> 해당 경로로 접속 URL이 구성되는지 확인할 것

배포 후 `admin.html`의 **행사 관리 표에서 각 행사의 "QR" 버튼**을 누르면 해당 행사 전용 QR코드가 표시됩니다.
접속 주소는 관리자 페이지 주소에서 자동으로 채워지며, 필요하면 "접속 주소 설정"에서 바꿀 수 있습니다.

### 7-0. 미션 문구·항목 편집

관리자 페이지 **"미션 설정"** 섹션에서 코드 배포 없이 수정할 수 있습니다.

- 미션 카드 제목·설명, 안내 화면 제목·문구, 제한시간
- 미션1 위험물/안전물품 목록, 미션3 직업-설명 짝, 미션2 배선 개수
- 안내 문구에는 `<strong>강조</strong>` 태그를 쓸 수 있습니다.
- **배점 공식은 코드에 고정**되어 있습니다(점수 일관성). 미션3은 짝당 20점 기준이므로 **6쌍 유지를 권장**합니다.
- 잘못된 설정(위험물만 있음, 짝 1개 등)은 저장 시 차단되며, 저장된 값이 비어 있으면 기본값이 사용됩니다.
- 참가자 화면은 **새로고침 시** 반영됩니다.

### 7-0-1. 행사별 미션 구성 (온/오프·순서)

행사 관리 표의 **"미션 구성"** 칸에 사용할 미션 번호를 순서대로 입력합니다.

| 입력 | 결과 |
|---|---|
| `1,2,3` | 미션 3개 모두, 기본 순서 (기본값) |
| `1,3` | 미션 1·3만 사용 (폭발물 미션 제외) |
| `3,1` | 미션 3 → 1 순서로 표시 |
| `2` | 미션 2 하나만 |

- 미션의 **내용**(문구·항목·제한시간)은 "미션 설정"에서 **공통으로** 관리되며, 행사별로는 구성만 다르게 지정합니다.

#### 여러 행사 동시 운영

- "진행중 노출"은 **여러 행사에 동시에 켤 수 있습니다.**
- 행사 전용 QR(`?event=<ID>`)로 접속하면 항상 해당 행사로 바로 연결됩니다.
- QR 없이 기본 주소로 접속했을 때는 **진행중인 행사 중에서 참가자가 선택**합니다. (진행중이 1개면 자동 연결, 기간이 지난 행사는 후보에서 제외)
- **인증서는 "켜둔 미션을 모두 완료"하면 발급**됩니다. 미션 2개짜리 행사는 2개만 끝내면 됩니다. 총점·총시간도 사용 중인 미션만 합산합니다.
- 잘못된 값(중복, 1~3 밖의 숫자, 빈 값)은 저장 시 차단되며, 값이 없으면 자동으로 `1,2,3`으로 동작합니다.

### 7-1. 기기별 참여 횟수 제한

한 기기에서 같은 행사에 **최대 2회**까지만 참여할 수 있습니다(`js/app.js`의 `MAX_PLAYS_PER_EVENT`).

- 집계 단위는 **행사별**이라, 다른 행사에서는 다시 2회 참여할 수 있습니다.
- **부스에 비치한 공용 기기**(여러 명이 순서대로 사용)는 이 제한에 걸리면 안 되므로, 해당 기기에서 `?kiosk=1`을 붙여 한 번 접속해 두면 제한이 면제됩니다. (해제는 `?kiosk=0`)
- 브라우저 `localStorage` 기반이라 **시크릿 모드나 캐시 삭제로 우회할 수 있습니다.** 로그인이 없는 구조에서의 한계이며, 완전 차단이 아닌 중복 참여 억제 수준으로 이해하세요.

  브라우저 콘솔에 색인 생성 링크가 표시될 수 있음 → 해당 링크 클릭해 색인 생성 필요 (확인 필요)
- 보안 규칙은 기본 시나리오만 검증된 상태이며, 악의적 클라이언트의 점수 조작(예: 직접 매우 높은 score 값으로 update)을
  완전히 막지는 못함 — 행사 성격(체험형, 경품 가치 낮음)을 고려해 허용 가능한 수준으로 판단했으나,
  보다 엄격한 검증이 필요하면 score 값 범위(0~100) 제한 규칙 추가 검토 필요 (확인 필요)
- 미션 게임 자체는 외부 서버 통신 없이 클라이언트에서만 동작하므로 와이파이가 일시적으로 끊겨도
  게임 진행은 가능하나, 완료 시점의 Firestore 저장은 재접속 후 재시도됨(자동 재시도 로직 미구현) (확인 필요)

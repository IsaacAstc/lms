# 구동 안내서 — 항공보안 교육 운영관리 시스템

이 문서는 **처음 보는 사람이 시스템을 직접 띄워 보고 주요 기능을 확인하는 순서**를 설명한다.
운영 세부(도메인·기관 분리·권한 등)는 [README](../README.md)를, 시연용 가상 데이터는 [DEMO.md](../DEMO.md)를 참고한다.

---

## 1. 구성 한눈에 보기

```
[브라우저] ── 정적 페이지(HTML/CSS/JS, GitHub Pages)
    │  Firebase Web SDK v10 (CDN, 빌드 도구 없음)
    ▼
[Firebase]
  ├─ Authentication   관리자 로그인(이메일/비밀번호)
  ├─ Firestore        운영 데이터 + 보안규칙(firestore.rules)
  ├─ Realtime DB      퀴즈·히어로 미션(선택)
  └─ Cloud Functions  (asia-northeast3, Node 22)
        ├─ 신청 접수·메일 발송·자동 파기
        └─ AI 기능 ─► OpenAI 호환 Chat Completions API
                       (OpenRouter · Ollama · vLLM · Upstage · CLOVA Studio 등 — 설정에서 교체)
```

- **서버 코드는 Cloud Functions뿐**이다. 화면은 정적 파일이라 어떤 정적 호스팅에도 올릴 수 있다.
- **AI 모델은 코드에 고정돼 있지 않다.** 화면의 `설정 → 기준값 설정 → AI 연결`에서 접속 주소·모델명·키만 바꾸면 다른 모델로 바뀐다(재배포 불필요).

## 2. 준비물

| 항목 | 용도 | 비고 |
|---|---|---|
| Firebase 프로젝트 | 인증·DB·함수 | Cloud Functions 때문에 **Blaze(종량제)** 필요 — 이 규모는 무료 구간 내 |
| Node.js 20+ / `firebase-tools` | 함수·규칙 배포 | 또는 GitHub Actions 자동 배포(4-3) |
| 정적 서버 | 로컬 실행 | `python3 -m http.server` 등 |
| AI 모델 접속 정보(선택) | AI 기능 | OpenAI 호환 API 주소 + 모델명 + 키 |
| Gmail 앱 비밀번호(선택) | 신청 접수 메일 | 신청 기능을 쓸 때만 |

## 3. 빠르게 띄워 보기 (로컬)

```bash
git clone <저장소 주소> lms && cd lms
cp js/firebase-config.example.js js/firebase-config.js
#  → js/firebase-config.js 에 Firebase 콘솔 > 프로젝트 설정 > 웹 앱 config 값 입력
python3 -m http.server 8000
#  → 브라우저에서 http://localhost:8000
```

1. Firebase 콘솔 → **Authentication → 로그인 방법 → 이메일/비밀번호** 사용 설정.
2. **Authentication → 사용자 추가**로 관리자 계정 생성(회원가입 화면은 없다).
3. **Authentication → 설정 → 승인된 도메인**에 `localhost`(및 배포 도메인) 확인.
4. Firestore 데이터베이스 생성(리전 `asia-northeast3` 권장) 후 보안규칙 배포:
   ```bash
   firebase login
   firebase use <프로젝트ID>
   firebase deploy --only firestore:rules
   ```
5. 첫 관리자를 마스터로 지정: Firestore 콘솔에서 `admins/{로그인 이메일(소문자)}` 문서를 만들고 `role: "master"` 필드 추가
   (또는 `functions/index.js`의 `BOOTSTRAP_ADMINS`에 등록된 계정 사용).
6. 로그인 → **설정 → 데이터 관리 → 초기 데이터 시드 실행**(강의실·커리큘럼·기준값 등록).

> `js/firebase-config.js`는 `.gitignore` 대상이다. 저장소가 공개이므로 설정값을 커밋하지 않는다.

## 4. 서버 함수 배포

### 4-1. 함수 시크릿
```bash
firebase functions:secrets:set MAIL_USER       # 발신 Gmail 주소
firebase functions:secrets:set MAIL_PASS       # Gmail 앱 비밀번호
firebase functions:secrets:set GH_FILES_TOKEN  # 자료실 파일 저장용 GitHub 토큰
```
### 4-2. 수동 배포
```bash
cd functions && npm install && cd ..
firebase deploy --only functions
```
### 4-3. 자동 배포(GitHub Actions)
`main`에 병합하면 `.github/workflows/deploy-functions.yml`이 함수·규칙을 배포한다.
저장소 Secrets에 `FIREBASE_SERVICE_ACCOUNT`(서비스 계정 JSON 전체), `FIREBASE_PROJECT_ID`를 등록한다
(추가 기관은 `_ATC`, 시연 기관은 `_DEMO` 접미사). 화면 배포는 `deploy.yml`이 `FIREBASE_*` 시크릿으로
`firebase-config.js`를 만들어 GitHub Pages에 올린다.

## 5. AI 연결 설정

AI 기능은 모두 **OpenAI 호환 Chat Completions** 한 가지 규격으로 호출한다.

1. 마스터 계정으로 **설정 → 기준값 설정 → AI 연결 (LLM)**.
2. **예시에서 추가…**로 프리셋을 고르거나 **빈 행 추가** 후 입력:

   | 칸 | 예 (OpenRouter) | 예 (자체 구축 Ollama) |
   |---|---|---|
   | 접속 주소 | `https://openrouter.ai/api/v1` | `http://<공개 접속 가능한 서버>:11434/v1` |
   | 모델명 | `google/gemma-4-26b-a4b-it` | `gpt-oss:20b` |
   | API 키 | `sk-or-v1-…` | (비움) |
   | JSON 모드 | 서버가 `response_format` 지원 시만 체크 | — |

3. **AI 연결 저장** → 행의 **테스트**. `연결 정상`과 응답 모델명이 표시되면 완료.
   테스트는 **저장된 값**으로 실행되므로 반드시 저장 후 누른다.
4. 여러 모델을 등록해 두고 **기본** 라디오로 기본 모델을 정한다. 각 기능 화면의 `모델` 선택 상자에서 실행마다 바꿀 수도 있다.

- **API 키는 서버(`aiKeys`)에만 저장**되며 보안규칙상 어떤 브라우저에서도 다시 읽을 수 없다(바꿀 때만 새로 입력).
- 함수가 모델을 호출하므로 `localhost`·내부망 주소는 닿지 않는다. 자체 구축 모델은 함수에서 접속 가능한 주소가 필요하다.
- 실행 이력은 하단 **최근 AI 실행 기록**에 모델·소요시간·결과만 남는다(원문은 남기지 않음).

| 오류 | 원인 | 조치 |
|---|---|---|
| HTTP 401 | 키 미전송·오류 | 키 칸을 지우고 다시 붙여넣기 → 저장 → 테스트 |
| HTTP 404 | 모델 ID 오타·무료 모델 정책 | 모델 페이지의 ID 복사, 제공처 개인정보 설정 확인 |
| HTTP 402 | 크레딧 부족 | 제공처 충전 |
| HTTP 429 | 제공처 혼잡·호출 제한 | 잠시 후 재시도 또는 다른 모델 선택 |

### AI 기능 상세

| 기능 | 위치 | AI가 하는 일 | 사람·시스템이 하는 일(안전장치) |
|---|---|---|---|
| 주관식 분석 | 주관식 원문 | 의견 분류, 시사점·반영계획 초안 | 서버에서 **이름·연락처 가림 처리 후** 전송, 분류는 정해진 목록만 허용, 적용은 사람이 선택 |

| 조치 추출 | 개선 추적 | 반영계획 글에서 조치 항목 추출·분류 | 등록할 항목은 사람이 고름, **효과 판정은 AI가 아닌 데이터 계산**(전·후 3개월 불만족 비율) |
| 공문 초안 | 공문 초안 | 공문서 문체 초안 | 강사 실명 미전송(○○○), 없는 사실은 ○○○ 자리, 숫자 대조 경고, 저장하지 않음 |

## 7. 개인정보·보안 요점

- 교육생 개인 식별정보 입력 필드가 없다. 설문은 로그인·이름·IP·User-Agent를 저장하지 않는다.
- 강사 실명은 관리자 전용 `instructors`에만 있고, **AI에는 보내지 않는다**(가림 처리·○○○ 표기).
- 응답 10명 미만 집계는 공개 산출물에서 마스킹한다(관리자 화면·내부 보고서는 실제 값).
- 보안규칙(`firestore.rules`)이 최종 방어선이다: 설문 응답은 생성만 공개, 읽기·수정은 관리자만. AI 키는 읽기 불가.
- 해외 AI 서비스(OpenRouter 등)는 **가상 데이터로 시연**하고, 운영 데이터 적용은 기관 지침 검토 후 내부 모델(Ollama·vLLM 등)로 전환한다 — 접속 주소만 바꾸면 된다.

## 8. 자주 묻는 문제

| 증상 | 확인 |
|---|---|
| 로그인 후 `Missing or insufficient permissions` | 보안규칙 미배포 또는 `admins/{email}` 문서 없음. 일반 관리자는 해당 탭 권한(`tabs`) 확인 |
| 로그인 팝업 오류 `auth/unauthorized-domain` | Authentication → 승인된 도메인에 접속 도메인 추가 |
| 화면이 빈 채로 멈춤 | `file://`로 열었는지 확인 — 정적 서버로 열어야 ES 모듈이 동작 |
| AI 버튼을 눌러도 오류 | 5절 표 참고, 설정 하단 **최근 AI 실행 기록**의 오류 메시지 확인 |
| 함수 배포 403 | 서비스 계정 역할(README '함수 자동 배포' 2번) 확인 |

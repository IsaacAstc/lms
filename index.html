기명 조사

이 메뉴는 개인정보를 수집합니다. 익명 설문과 저장 위치·응답 페이지가 완전히 분리되어 있으며, 여기서 만든 조사는 개인정보파일에 해당합니다. 조사를 열기 전에 개인정보 보호 담당부서의 확인(개인정보파일 등록·동의 문안·보유기간)을 받으세요.

응답자 식별자는 서버에서 되돌릴 수 없는 형태로 변환한 뒤 응답과 분리해 보관합니다. 중복 응답 판정에만 쓰이고 응답 내용과 연결되지 않으므로, 어떤 응답이 누구의 것인지는 시스템에서도 알 수 없습니다. 사진·연락처 등 선택 목적 항목은 저장하지 않고 담당자 메일로만 전달되며, 메일함에서 삭제해야 파기가 완료됩니다.

⚙ 최초 1회: Firebase 콘솔에서 namedRespondents 복합 인덱스(surveyId + collectedDate)를 만들어야 기간 지정 파기가 동작합니다. 자세한 내용은 저장소의 firestore-indexes.md를 참고하세요.

응답 조회·내보내기·파기는 모두 접속기록으로 남습니다(계정·일시·접속지·수행업무·건수, 1년 보관, 수정·삭제 불가). 내보내기와 파기는 사유 입력이 필요합니다. 접속기록은 월 1회 이상 점검하고 🗂 접속기록 화면에서 점검 기록을 남기세요.

설문 문항 설정

문항을 세트로 여러 벌 만들어 과정(커리큘럼)·차수별로 다르게 연결할 수 있습니다. 적용 우선순위는 차수 지정 > 커리큘럼 지정 > 기본 세트입니다.

여기서 정한 문항은 이후 생성되는 설문에 적용됩니다. 이미 수집된 응답은 응답 당시 문항으로 집계·표시되므로 과거 보고서는 바뀌지 않습니다. 문항을 개정하면 발효일자를 지정해 개정본으로 등록하세요.

고정 카테고리 (교육·강사 만족도)

100점 환산 요약·과정유형별 비교·강사별 집계 등 보고서 표준의 뼈대라 카테고리 자체는 고정입니다(제목 수정·문항 편집·0개 비우기 가능).

교육 만족도 문항 (5점 척도)

강사 만족도 문항 (5점 척도 · 강사별 반복)

문항 카테고리

카테고리 안에 5점 척도 / 예·아니오 / 주관식 / 선다형(택1) / 복수 응답 / 사진 첨부 / 안내 문구 / 조건부 후속을 자유롭게 섞어 추가하고, ◀▶(문항)·▲▼(카테고리)로 순서를 조정합니다. 선다형/복수 응답의 보기는 " / "로 구분해 입력합니다.

문항마다 필수 체크로 응답 의무를 개별 지정합니다. 새 문항은 필수 상태로 추가되며, 체크를 해제하면 응답자 화면에 (선택)으로 표시되고 비워 둔 채 제출할 수 있습니다(안내 문구는 응답이 없어 해당 없음). 필수 여부를 지정하기 전에 만든 문항은 종전 동작대로 객관식은 필수, 주관식·첨부는 선택으로 유지됩니다.

[기본·불만족]·[기본·제안개선] 표식이 붙은 주관식은 원문 분류·보고서 2종 구분에 쓰이는 기본 주관식입니다. 아무 카테고리로나 옮기거나 삭제할 수 있고, 삭제한 경우 아래 '복원' 버튼으로 되살립니다.

조건부 후속은 앞선 문항(교육·카테고리 5점 → N점 이하 / O·X → 예·아니오 선택)의 답변에 따라 그 문항 바로 아래에 노출되는 1단계 분기 문항입니다. 후속 유형은 주관식·예/아니오·사진 첨부·메일 전용 입력 중 선택하며, 필수 여부도 지정할 수 있습니다(노출된 경우에만 적용). 주관식 원문은 '주관식 원문' 탭에 조건부 종류로, O/X는 예/아니오 집계표에 포함되고, 사진·메일 전용 입력은 담당자 메일로만 전달됩니다.

안내 문구는 응답 입력 없이 설명만 보여주는 유형입니다(동의 안내·구간 설명 등). 문항 번호에서 제외되고 집계에도 포함되지 않으며, 줄바꿈이 그대로 표시됩니다.

사진 첨부·메일 전용 입력은 값이 시스템에 저장되지 않고 담당자 메일로만 전달됩니다(연락처 등 개인정보 수집 최소화). 두 유형이 함께 있는 설문에서는 모두 입력한 경우에만 메일이 발송되며, 일부만 입력하면 안내 후 설문 응답만 기록됩니다. 수신 주소는 설문 관리 탭의 📧 버튼에서 차수별로 지정합니다.

집계 방식 — 5점: 100점 환산 표 · 예/아니오: '예' 비율(%) · 선다형/복수: 보기 분포. 모두 설문 집계 탭과 운영 보고서(2-1절), 통계 탭(기간 합산)에 표시됩니다.

관리자 목록

마스터 관리자는 관리자 삭제·역할 변경과 ‘데이터 관리’(설문 원문 파기 등)를 사용할 수 있습니다. 일반 관리자는 그 두 가지가 제외되며, 나머지 운영 기능은 동일합니다. 삭제는 관리자 권한(allowlist)만 회수하며 Auth 계정 완전 삭제는 Firebase 콘솔에서 처리합니다. 부트스트랩 마스터는 보안규칙에 고정되어 목록에 표시되지 않습니다.

원문 현황 (누적량 모니터링)

설문 원문 문서 수를 저비용(count)으로 측정해 임계값 대비 현황을 표시합니다. 실제 Firebase 사용량과는 별개의 추정 지표입니다.

원문 파기 (수집일 범위)

지정한 수집일 범위의 설문 원문을 삭제합니다. 삭제 전 월별 집계 스냅샷을 저장하므로 집계·보고서는 이후에도 조회할 수 있습니다(주관식 원문만 사라짐). 되돌릴 수 없습니다.



          
미연결 시간표 정리

          
삭제된 차수에 남아 있는 시간표 세션(과정과 연결되지 않은 세션)과 공개설문을 찾아 정리합니다. 먼저 검사한 뒤 삭제합니다.

공개 현황 보드

          
외부 접속자가 교육 과정별 일자·정원·신청·잔여석을 실시간으로 볼 수 있는 공개 페이지입니다. 개인정보는 노출되지 않으며(수치·일정만), 실제 신청 접수는 시스템 범위 밖입니다. 숨김 처리한 차수는 게시되지 않으며, 과정유형이 특별·재교육인 차수는 이 공개 보드에는 숨겨지고 현장 안내 DID에만 표시됩니다. 예정(계획)으로 표시한 차수는 과정명 앞에 (예정)이 붙어 게시됩니다. 차수를 저장하면 자동으로 반영되고, 기존 차수는 아래 ‘전체 동기화’로 한 번에 게시합니다.

신청 방법 안내 문구

          
보드 하단에 노출됩니다. 실제 신청 경로(오프라인/외부 링크 등)를 안내하세요. 개인정보 입력을 요구하지 않도록 문구를 작성합니다.

          
          


          
온라인 신청 접수 (이메일 자동 발송)

          
접수 이메일을 설정하고 활성화하면 공개 보드에 신청/취소 버튼이 나타납니다. 신청 시 접수 메일이 이 주소와 신청자 본인에게 자동 발송되고, 잔여석이 즉시 보드에 반영됩니다. 취소는 신청 시 발급된 접수번호로만 가능합니다. 신청자 이메일·첨부파일은 메일 발송에만 쓰이고 시스템에 저장되지 않습니다. Cloud Functions 배포(Blaze 플랜) 후 동작합니다 — 배포 방법은 README 참고.

          

            
            
            
          

          
신청 접수 이력

          
Cloud Function이 기록한 접수 현황입니다(접수번호 해시·수치·상태만 저장). 상세 내용·첨부는 접수 이메일함에서 확인하세요.
            공문·명단이 미비하면 반려를 눌러 처리하세요 — 잔여석이 즉시 복구되고 신청자에게 반려 사유가 메일로 통지되며, 해당 접수번호는 사용할 수 없게 됩니다.
            반려 통지를 위해 신청자 이메일을 신청 마감일(교육 시작일)까지만 보관하며, 반려·취소 처리 시 즉시 파기합니다.

기관 관리

          
교육기관 단위로 시스템을 분리 운영합니다. 각 기관은 별도의 Firebase 프로젝트를 사용해 차수·시간표·마스터·설문 데이터가 완전히 격리됩니다.
            신규 기관 절차: ① Firebase 콘솔에서 프로젝트 생성(Firestore·Authentication 활성화, firestore.rules 게시, 관리자 계정 생성) ② 아래에 설정값(config) 등록.
            등록된 기관은 로그인 화면·상단바의 기관 선택에 나타납니다.
